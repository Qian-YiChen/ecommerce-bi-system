【重要经验与避坑指南（来自skill.txt）】

  1. Python环境：
     - 只能用 D:\Anaconda\python.exe
     - WindowsApps下的python3会超时/权限受限，绝对不要用
     - pip安装也用完整路径：D:\Anaconda\python.exe -m pip install ...

  2. MySQL相关：
     - mysqld（带d=daemon/服务器）≠ mysql（客户端）
     - 必须先启动mysqld才能连接
     - MySQL 8.4 不支持 default_authentication_plugin=mysql_native_password 参数
     - 数据物理位置：每个库=一个子目录，每张InnoDB表=一个.ibd文件
     - 数据目录不能放Program Files下（权限不够）
     - DECIMAL(5,4)只能存到9.9999，MAPE百分比值需DECIMAL(8,2)以上

  3. ML模块：
     - pd.read_sql()直接传pymysql.Connection会UserWarning，但能工作
     - 线性回归基线模型MAPE可能100%+，小数据集正常
     - 递归预测只能用lag_1不能用lag_7/lag_30（未来值不存在，无法更新）
     - 库存数据必须来自数据库，不能用MOCK_INVENTORY随机生成
     - ML必须提供独立API函数——不能只靠main()一次性跑全流程
     - 全局模型需category_id特征区分品类（否则手机和零食共用一个预测公式）

  4. 认证模块：
     - auth_service使用依赖注入（login接收get_user_fn参数）
     - 测试用mock替代真实数据库（不连MySQL也能验证业务逻辑）
     - patch目标必须是被import的位置，不是定义位置
     - JWT是无状态认证——解码不需查库，安全靠签名

  5. Git操作：
     - 只上传工程/文件夹
     - Token绝对不能写入会被push的文件（GitHub Push Protection会扫描）
     - amend后commit hash会变，已push过的不要amend
     - fetch先看别人改了什么（git diff HEAD..origin/main），再pull
     - commit message不能为空（至少写个"update"）

  6. 文件编辑：
     - sed处理中文全角字符（如（）「」）容易报错，用Python替代
     - Windows终端默认GBK，print emoji会UnicodeEncodeError
     - 用 io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8') 解决

  7. 文档与代码一致性：
     - 每次组员交付后必须交叉比对：docs vs 实际代码 vs 项目结构总览
     - 函数参数需求文档的签名必须和实际代码严格一致
     - 设计文档中模块名应与实际文件结构对应
     - 表数量变更需同步更新所有文档
     - 当前已知不一致（已修复，但将来可能再次出现）：
       函数签名、表数量、模块名、API路径

  8. 数据库种子数据：
     - 当前为手写INSERT（163条销售记录）
     - 如数据量不足导致ML效果差（MAPE>100%），属正常
     - 苏文韬待生成随机数据扩量
