## 五、数据来源与流向

```
                    苏文韬（数据管道）
                    ┌──────────────────────┐
  种子数据（手写）    │  • init.sql 完整 DDL   │
  + Python Faker     │  • 10张表种子数据      │
  （待补充）          │  • 待：随机数据生成脚本  │
                    └──────┬───────────────┘
                           │ MySQL 数据库
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
    薛淞（ML训练）     严辰乐/苏文韬      闫维岳/姚凯曦
   ┌──────────┐   ┌──────────────┐   ┌──────────┐
   │ 从MySQL   │   │ 后端API查询   │   │ 前端展示   │
   │ 取数训练   │   │ 返回JSON     │   │ ECharts   │
   │ 模型输出   │   │              │   │ 图表渲染   │
   └──────────┘   └──────────────┘   └──────────┘
```

| 环节 | 负责人 | 具体操作 | 产出 |
|------|--------|----------|------|
| 种子数据 | 苏文韬 | init.sql 含手写 INSERT：2用户 + 17品类 + 24商品 + 20客户 + 163销售记录 + 20用户画像 + 3告警规则 | 种子 SQL 文件 |
| 随机数据生成（新增） | 苏文韬 | 用 Python Faker/numpy 生成更大量模拟数据（目标：≥1000条销售记录），替换手写种子 | 数据生成脚本 + 更新后的 init.sql |
| ML训练数据 | 薛淞 | 从 MySQL `sales_record` 表读取历史销售数据，从 `product`/`customer` 表读取维度信息 | Pandas DataFrame |
| 测试数据 | 姚凯曦 | 从 MySQL 导出子集作为测试用例数据，补充边界场景的模拟数据 | 测试数据集 |
| 竞品数据（P2） | 苏文韬 | 手动录入3-5个竞品的关键指标（价格、销量估算），存 `campaign` 或新表 | 竞品对比数据 |

> **数据来源**：当前为手写种子数据（163条销售记录，覆盖24个商品）。为增加真实性和数据量，苏文韬需编写随机数据生成脚本（Python Faker 或 numpy），目标 ≥1000 条销售记录，覆盖更长时间跨度和更多场景。

## 六、协作规则（2周生死版）

1. **每天必报**：每人每晚在群内发三句话——今天做了什么 / 明天做什么 / 有没有卡点。不要求格式，但必须发
2. **接口文档第2天锁死**：第2天结束前，严辰乐+苏文韬产出 API 接口文档（请求/响应JSON格式），之后前后端据此并行开发，互不等待
3. **数据库第1天出DDL**：苏文韬第1天输出建表SQL（10张表），所有人据此建本地库
4. **数据第1天就位**：苏文韬第1天下载 Kaggle 数据集并导入 MySQL，薛淞当天从 MySQL 取数开始跑模型。不要各自找数据、不要等
5. **ML第1天跑通基线**：薛淞第1天用线性回归跑通预测全流程（数据→训练→输出），后续再换ARIMA优化，不要一上来就调参
5. **Git分支**：`main`（稳定）/ `dev`（集成）/ 每人一个分支，每天至少push一次
6. **P0铁律**：第8天如果P0还没跑通，立即全体停下手头工作集中攻坚P0，P1/P2直接砍
7. **演示优先**：第10天起，一切以"课堂上能演示什么"为决策标准，功能不完整没关系，但要能跑、不报错
