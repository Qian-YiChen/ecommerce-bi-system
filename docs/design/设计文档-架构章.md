## 2.2 技术栈

| 层次 | 技术 | 版本要求 | 选型理由 |
|------|------|----------|----------|
| **前端框架** | Vue 3 | ≥3.3 | 组件化开发，Element Plus 提供企业级 UI 组件，ECharts 图表生态成熟 |
| **UI 组件库** | Element Plus | ≥2.4 | 开箱即用的表格/表单/筛选器/弹窗组件，减少前端开发量 |
| **图表库** | ECharts | 5.x | 支持折线/柱状/饼图/热力图/漏斗图，交互丰富，中文文档完善 |
| **后端框架** | Flask | 3.x | 轻量级，适合中小型 API 服务，学习成本低，组员有经验 |
| **认证** | PyJWT + bcrypt | — | JWT 无状态认证，bcrypt 单向哈希不可逆 |
| **数据库** | MySQL | 8.0+ | 关系型数据，事务支持，课程标配 |
| **数据库驱动** | PyMySQL | ≥1.1 | 纯 Python 实现，无需编译 MySQL 客户端 |
| **ML 框架** | scikit-learn | ≥1.3 | 提供线性回归、ARIMA（statsmodels）、协同过滤等成熟算法 |
| **定时任务** | APScheduler | ≥3.10 | 预警定时扫描（每小时），轻量级，无需独立调度系统 |
| **部署** | Docker Compose | — | 一键拉起前后端+数据库+ML服务，解决环境差异问题 |

## 2.4 技术关键点

| 关键点 | 说明 |
|--------|------|
| **前后端分离** | 前端 Vue3 (port 5173) ← RESTful API → 后端 Flask (port 5000)，CORS 跨域 |
| **无状态认证** | JWT Token，不依赖服务端 Session，方便扩展 |
| **ML 服务解耦** | 预测模型作为独立模块被后端 import 调用，也可拆为独立进程通过 HTTP 通信 |
| **定时预警** | APScheduler 每 1 小时扫描 sales_record，与基线对比，触发告警 |
| **文件导出** | 后端生成文件，返回 URL 供前端下载，大数据量异步生成 |
| **Python 环境** | 统一使用 D:\Anaconda\python.exe（Python 3.13.9），不混用系统自带 Python |
