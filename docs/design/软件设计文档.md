## 1. 引言

### 1.1 编写目的

本文档基于《需求分析文档》v1.0，对系统进行概要设计和详细设计，作为编码实现和测试的基准依据。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 分层解耦 | 表现层、业务逻辑层、数据访问层、ML服务层独立，通过接口通信 |
| 高内聚低耦合 | 每个模块职责单一，模块间通过 RESTful API 或函数调用协作 |
| 可扩展 | 新增数据维度/预测模型/推荐策略时不影响已有功能 |
| 可部署 | 提供 Docker Compose 一键部署 |

## 2. 总体设计

### 2.1 架构设计

采用 **B/S 四层架构**：

```
┌─────────────────────────────────────────┐
│            表现层（Presentation）         │
│         Vue 3 + Element Plus + ECharts   │
│   闫维岳（核心页面）  姚凯曦（管理页面）    │
└────────────────┬────────────────────────┘
                 │ RESTful API (JSON) + JWT
┌────────────────▼────────────────────────┐
│         业务逻辑层（Business Logic）       │
│              Python Flask 3.x            │
│   严辰乐：认证/预测集成/预警调度            │
│   苏文韬：数据查询/报表导出                │
└──────┬────────────────────┬─────────────┘
       │ PyMySQL            │ import
┌──────▼──────────┐  ┌──────▼──────────┐
│  数据访问层       │  │  ML 服务层       │
│  MySQL 8.0      │  │  scikit-learn   │
│  苏文韬          │  │  薛淞            │
└─────────────────┘  └─────────────────┘
```

### 2.2 技术栈

| 层次 | 技术 | 版本 |
|------|------|------|
| 前端框架 | Vue 3 | ≥3.3 |
| UI 组件库 | Element Plus | ≥2.4 |
| 图表库 | ECharts | 5.x |
| 后端框架 | Flask | 3.x |
| 认证 | PyJWT + bcrypt | — |
| 数据库 | MySQL | 8.0+ |
| 数据库驱动 | PyMySQL | ≥1.1 |
| ML 框架 | scikit-learn + statsmodels | ≥1.3 |
| 定时任务 | APScheduler | ≥3.10 |
| 部署 | Docker Compose | — |

## 4. 接口设计

### 4.1 统一响应格式

```json
// 成功
{ "success": true, "data": {...}, "message": "ok" }

// 失败
{ "success": false, "data": null, "error": "描述", "code": "ERROR_CODE" }
```

### 4.2 认证接口

| 方法 | 路径 | 说明 | 需Token | 请求体 |
|------|------|------|---------|--------|
| POST | /api/auth/login | 登录 | 否 | `{username, password}` |
| POST | /api/auth/register | 注册用户 | 是(admin) | `{username, password, role}` |
| GET | /api/auth/me | 当前用户信息 | 是 | — |

### 4.3 数据查询接口

| 方法 | 路径 | 说明 | 需Token | 参数 |
|------|------|------|---------|------|
| GET | /api/data/query | 多维度销售查询 | 是 | `start_date, end_date, region?, category_id?, channel?, group_by` |
| GET | /api/data/export | 导出查询结果 | 是 | 同上 + `format(pdf/excel/png)` |

### 4.4 预测接口

| 方法 | 路径 | 说明 | 需Token | 请求体 |
|------|------|------|---------|--------|
| GET | /api/predict/sales | 获取最新销售预测结果 | 是 | — |
| GET | /api/predict/stock | 获取补货建议 | 是 | — |
| GET | /api/alert/scan | 触发异常检测扫描 | 是 | — |

> 注：ML 模型为同步调用（非异步任务模式），故无需 task_id 查询步骤。
> 预测固定为 7 天、全品类，参数扩展留待后续迭代。

### 4.5 预警接口

| 方法 | 路径 | 说明 | 需Token | 
|------|------|------|---------|
| GET | /api/alert/rules | 获取预警规则列表 | 是 |
| POST | /api/alert/rules | 创建预警规则 | 是(admin) |
| PUT | /api/alert/rules/{id} | 更新预警规则 | 是(admin) |
| GET | /api/alert/logs | 获取预警日志 | 是 |
| PUT | /api/alert/logs/{id}/resolve | 标记已处理 | 是 |
| POST | /api/alert/scan | 手动触发扫描 | 是 |

### 4.6 报表接口

| 方法 | 路径 | 说明 | 需Token |
|------|------|------|---------|
| POST | /api/report/generate | 生成报表 | 是 |
| GET | /api/report/download/{file_id} | 下载报表文件 | 是 |

### 4.7 外部接口

| 接口 | 方向 | 协议 | 说明 |
|------|------|------|------|
| 电商数据导入 | 入站 | CSV/Excel 上传 | 文件上传 → 自动解析 → 入库 |
| 外部数据源接入 | 入站 | RESTful / JDBC | 预留，对接电商平台 |
| 预测结果开放 API | 出站 | RESTful GET | 可选，需 API Key |
| 邮件告警 | 出站 | SMTP | 预警触发时发送 |

## 5. 界面设计

### 5.1 整体风格

- 企业级 BI 仪表盘风格，深色/浅色主题可切换
- 左侧可折叠导航（按功能模块分组）
- 顶部：搜索栏 + 通知图标 + 用户头像下拉菜单
- 主区域：面包屑导航 + 内容区

### 5.2 核心页面布局

```
┌──────────────────────────────────────────────┐
│  Logo    [搜索框]         🔔  👤 用户名  ▼   │  ← 顶栏
├────────┬─────────────────────────────────────┤
│ 仪表盘  │  面包屑：首页 > 数据查询              │
│ 数据查询 │                                     │
│ 销售预测 │  ┌─────────┐ ┌─────────┐ ┌──────┐  │
│ 库存预测 │  │ 总GMV    │ │ 订单量   │ │ 毛利率 │  │  ← 指标卡片
│ 用户画像 │  │ ¥12.3M  │ │ 5,678  │ │ 32%  │  │
│ 报表中心 │  └─────────┘ └─────────┘ └──────┘  │
│ 预警中心 │                                     │
│ ─────── │  ┌─────────────────────────────┐   │
│ 用户管理 │  │                             │   │  ← 图表区
│ 数据源   │  │      折线图 / 柱状图         │   │
│         │  │                             │   │
│         │  └─────────────────────────────┘   │
│         │                                     │
│         │  ┌─────────────────────────────┐   │
│         │  │  数据表格（可排序/筛选/分页）  │   │  ← 表格区
│         │  └─────────────────────────────┘   │
└────────┴─────────────────────────────────────┘
```

### 5.3 交互规范

| 交互 | 规范 |
|------|------|
| 数据加载 | 骨架屏占位，不出现空白页 |
| 空状态 | 插图 + "暂无数据" 提示文案 |
| 错误提示 | 中文描述 + 解决建议（如"请检查网络连接后重试"） |
| 图表 | 悬停显示详情、点击下钻、拖拽缩放时间范围 |
| 表格 | 列排序/筛选、自定义列显示、分页默认20条 |
| 导出 | 点击后显示进度，完成后自动下载 |

## 6. 数据库设计

> ⏳ 本章等苏文韬交付 DDL 后补充完整 ER 图和表结构说明。
> 数据字典详见《需求分析文档》§6.2。

### 6.1 核心表清单（共10张）

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| user | 系统用户 | user_id, username, password(哈希), role, status |
| category | 商品品类 | category_id, category_name, parent_id, level |
| product | 商品 | product_id, product_name, sku_code, category_id, price, cost |
| sales_record | 销售记录（核心事实表） | record_id, product_id, customer_id, quantity, total_amount, order_date, region, channel |
| customer | 客户 | customer_id, customer_name, gender, age_group, region |
| user_profile | 用户画像 | profile_id, customer_id, value_level, avg_order_price, purchase_frequency |
| sales_forecast | 销售预测结果 | forecast_id, product_id, forecast_date, predicted_quantity, confidence_lower/upper, model_type |
| alert_rule | 预警规则 | rule_id, rule_name, rule_type, threshold, product_id, is_enabled |
| alert_log | 预警日志 | log_id, rule_id, trigger_time, alert_content, anomaly_value, baseline_value, status |
| campaign | 营销活动 | campaign_id, campaign_name, start/end_date, discount_rate, affected_product_ids, campaign_cost |

### 6.2 表关系

```
category ──(1:N)── product ──(1:N)── sales_record ──(N:1)── customer
                │                    │
                │                    └──(1:1)── user_profile
                │
                └──(1:N)── sales_forecast
                └──(1:N)── alert_rule ──(1:N)── alert_log
                
campaign（独立，通过 affected_product_ids JSON 关联 product）
user（独立，系统用户，与业务表无直接外键）
```
