## 2. 总体设计

### 2.1 架构设计

采用 **B/S 四层架构**：

```
┌─────────────────────────────────────────┐
│            表现层（Presentation）         │
│         Vue 3 + Element Plus + ECharts   │
│   闫维岳（核心页面）  姚凯曦（管理页面）    │
└────────────────┬────────────────────────┘
                 │ RESTful API (JSON) + JWT
┌────────────────▼────────────────────────┐
│         业务逻辑层（Business Logic）       │
│              Python Flask 3.x            │
│   严辰乐：认证/预测集成/预警调度            │
│   苏文韬：数据查询/报表导出                │
└──────┬────────────────────┬─────────────┘
       │ PyMySQL            │ import
┌──────▼──────────┐  ┌──────▼──────────┐
│  数据访问层       │  │  ML 服务层       │
│  MySQL 8.0      │  │  scikit-learn   │
│  苏文韬          │  │  薛淞            │
└─────────────────┘  └─────────────────┘
```

### 2.2 技术栈

| 层次 | 技术 | 版本 |

## 4. 接口设计

### 4.1 统一响应格式

```json
// 成功
{ "success": true, "data": {...}, "message": "ok" }

// 失败
{ "success": false, "data": null, "error": "描述", "code": "ERROR_CODE" }
```

### 4.2 认证接口

| 方法 | 路径 | 说明 | 需Token | 请求体 |
|------|------|------|---------|--------|
| POST | /api/auth/login | 登录 | 否 | `{username, password}` |
| POST | /api/auth/register | 注册用户 | 是(admin) | `{username, password, role}` |
| GET | /api/auth/me | 当前用户信息 | 是 | — |

### 4.3 数据查询接口

| 方法 | 路径 | 说明 | 需Token | 参数 |
|------|------|------|---------|------|
| GET | /api/data/query | 多维度销售查询 | 是 | `start_date, end_date, region?, category_id?, channel?, group_by` |
| GET | /api/data/export | 导出查询结果 | 是 | 同上 + `format(pdf/excel/png)` |

### 4.4 预测接口

| 方法 | 路径 | 说明 | 需Token | 请求体 |
|------|------|------|---------|--------|
| GET | /api/predict/sales | 获取最新销售预测结果 | 是 | — |
| GET | /api/predict/stock | 获取补货建议 | 是 | — |
| GET | /api/alert/scan | 触发异常检测扫描 | 是 | — |

> 注：ML 模型为同步调用（非异步任务模式），故无需 task_id 查询步骤。
> 预测固定为 7 天、全品类，参数扩展留待后续迭代。

### 4.5 预警接口

| 方法 | 路径 | 说明 | 需Token | 
|------|------|------|---------|
| GET | /api/alert/rules | 获取预警规则列表 | 是 |
| POST | /api/alert/rules | 创建预警规则 | 是(admin) |
| PUT | /api/alert/rules/{id} | 更新预警规则 | 是(admin) |
| GET | /api/alert/logs | 获取预警日志 | 是 |
| PUT | /api/alert/logs/{id}/resolve | 标记已处理 | 是 |
| POST | /api/alert/scan | 手动触发扫描 | 是 |

### 4.6 报表接口

| 方法 | 路径 | 说明 | 需Token |
|------|------|------|---------|
| POST | /api/report/generate | 生成报表 | 是 |
| GET | /api/report/download/{file_id} | 下载报表文件 | 是 |

### 4.7 外部接口

| 接口 | 方向 | 协议 | 说明 |
|------|------|------|------|
| 电商数据导入 | 入站 | CSV/Excel 上传 | 文件上传 → 自动解析 → 入库 |
| 外部数据源接入 | 入站 | RESTful / JDBC | 预留，对接电商平台 |
| 预测结果开放 API | 出站 | RESTful GET | 可选，需 API Key |
| 邮件告警 | 出站 | SMTP | 预警触发时发送 |

### 6.1 设计概述

#### 6.1.1 设计目标

| 目标 | 说明 |
|------|------|
| 业务完整性 | 覆盖电商BI核心业务域：商品、销售、客户、预测、预警、营销 |

- **引擎**：InnoDB（支持事务、行锁、外键约束）
- **字符集**：utf8mb4
- **排序规则**：utf8mb4_unicode_ci

#### 6.1.3 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 表名 | 小写 + 下划线，单数形式 | `sales_record` |
| 主键 | `{表名}_id` | `product_id` |
| 外键 | `fk_{从表}_{主表}` | `fk_product_category` |
| 唯一键 | `uk_{字段名}` | `uk_username` |
| 普通索引 | `idx_{字段名}` | `idx_order_date` |
| 复合索引 | `idx_{字段1}_{字段2}` | `idx_date_region` |

### 6.3 详细表结构

#### 6.3.1 user — 系统用户表

**用途**：系统登录认证与 RBAC 权限管理。密码以 bcrypt 哈希存储，不存明文。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `user_id` | INT | PK, AUTO_INCREMENT | — | 用户ID |
| `username` | VARCHAR(50) | NOT NULL, UNIQUE | — | 用户名 |
| `password` | VARCHAR(255) | NOT NULL | — | bcrypt 密码哈希 |
| `role` | VARCHAR(20) | NOT NULL | `'viewer'` | admin / analyst / manager / viewer |
| `status` | TINYINT | NOT NULL | `1` | 1=活跃 0=禁用 |
| `created_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 创建时间 |

**索引**：PRIMARY(`user_id`), UNIQUE(`username`), INDEX(`role`), INDEX(`status`)

---

#### 6.3.2 category — 品类表

**用途**：支持三级品类层级树（一级→二级→三级），parent_id 自引用。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `category_id` | INT | PK, AUTO_INCREMENT | — | 品类ID |
| `category_name` | VARCHAR(50) | NOT NULL | — | 品类名称 |
| `parent_id` | INT | FK→category, NULL | NULL | 父品类ID，NULL=一级 |
| `level` | TINYINT | NOT NULL | — | 1=一级 2=二级 3=三级 |

**外键**：`parent_id` → `category(category_id)` ON DELETE SET NULL

**索引**：PRIMARY(`category_id`), INDEX(`parent_id`), INDEX(`level`)

**种子数据**：4个一级类目 + 12个二级子类（服装鞋包、数码电子、食品饮料、家居用品）

---

#### 6.3.3 product — 商品表

**用途**：商品主数据，关联品类，记录价格/成本/库存。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `product_id` | INT | PK, AUTO_INCREMENT | — | 商品ID |
| `product_name` | VARCHAR(200) | NOT NULL | — | 商品名称 |
| `sku_code` | VARCHAR(50) | NOT NULL, UNIQUE | — | SKU编码 |
| `category_id` | INT | FK→category, NOT NULL | — | 所属品类 |
| `price` | DECIMAL(10,2) | NOT NULL | — | 销售单价（元） |
| `cost` | DECIMAL(10,2) | — | NULL | 进货成本（元） |
| `stock_quantity` | INT | NOT NULL | `0` | 当前库存量 |
| `status` | TINYINT | NOT NULL | `1` | 1=在售 0=下架 |
| `created_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 创建时间 |

**外键**：`category_id` → `category(category_id)` ON DELETE RESTRICT

**索引**：PRIMARY(`product_id`), UNIQUE(`sku_code`), INDEX(`category_id`), INDEX(`status`), INDEX(`price`)

---

#### 6.3.4 customer — 客户表

**用途**：消费者脱敏基础信息，供用户画像和区域分析使用。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `customer_id` | INT | PK, AUTO_INCREMENT | — | 客户ID |
| `customer_name` | VARCHAR(50) | — | NULL | 客户昵称（可匿名） |
| `gender` | CHAR(1) | — | NULL | M=男 F=女 U=未知 |
| `age_group` | VARCHAR(10) | — | NULL | 18-24 / 25-34 / 35-44 / 45+ |
| `region` | VARCHAR(30) | — | NULL | 所在省份 |
| `register_date` | DATE | — | NULL | 注册日期 |

**索引**：PRIMARY(`customer_id`), INDEX(`region`), INDEX(`age_group`), INDEX(`gender`)

---

#### 6.3.5 sales_record — 销售记录表（核心事实表）

**用途**：系统最大、查询最频繁的表。记录每笔订单明细，支撑多维聚合分析。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `record_id` | BIGINT | PK, AUTO_INCREMENT | — | 记录ID |
| `product_id` | INT | FK→product, NOT NULL | — | 商品ID |
| `customer_id` | INT | FK→customer, NULL | NULL | 客户ID（匿名可为NULL） |
| `quantity` | INT | NOT NULL | — | 销售数量 |
| `unit_price` | DECIMAL(10,2) | NOT NULL | — | 实际成交单价（元） |
| `total_amount` | DECIMAL(12,2) | NOT NULL | — | 成交金额（元） |
| `order_date` | DATETIME | NOT NULL | — | 下单时间 |
| `region` | VARCHAR(30) | NOT NULL | — | 收货省份 |
| `channel` | VARCHAR(20) | NOT NULL | `'PC'` | PC / Mobile / Miniprogram |

**外键**：
- `product_id` → `product(product_id)` ON DELETE RESTRICT
- `customer_id` → `customer(customer_id)` ON DELETE SET NULL

**索引**：
- PRIMARY(`record_id`)
- INDEX(`product_id`), INDEX(`customer_id`)
- INDEX(`order_date`), INDEX(`region`), INDEX(`channel`)
- 复合索引：`idx_date_region`(`order_date`, `region`), `idx_date_product`(`order_date`, `product_id`)

**查询模式**：时间范围 + 可选维度（region/category_id/channel）→ GROUP BY 聚合。详见 `db_service.py` → `query_sales()`。

---

#### 6.3.6 user_profile — 用户画像表

**用途**：存储 ML 管道（RFM 模型）计算得出的客户价值分层与消费行为标签。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `profile_id` | INT | PK, AUTO_INCREMENT | — | 画像ID |
| `customer_id` | INT | FK→customer, UNIQUE | — | 客户ID（一对一） |
| `value_level` | VARCHAR(10) | NOT NULL | — | 高价值 / 中价值 / 低价值 |
| `avg_order_price` | DECIMAL(10,2) | NOT NULL | — | 平均客单价（元） |
| `purchase_frequency` | DECIMAL(5,2) | NOT NULL | — | 月均购买次数 |
| `preferred_category` | VARCHAR(100) | — | NULL | 偏好品类（逗号分隔） |
| `promo_sensitivity` | VARCHAR(10) | — | NULL | 促销敏感度：高/中/低 |
| `last_purchase_date` | DATE | — | NULL | 最近购买日期 |
| `updated_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP ON UPDATE` | 更新时间 |

**外键**：`customer_id` → `customer(customer_id)` ON DELETE CASCADE

**索引**：PRIMARY(`profile_id`), UNIQUE(`customer_id`), INDEX(`value_level`), INDEX(`last_purchase_date`)

#### 6.3.7 sales_forecast — 销售预测表

**用途**：存储 ML 模型预测的未来销量、置信区间和模型指标。

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|------|------|------|--------|------|
| `forecast_id` | BIGINT | PK, AUTO_INCREMENT | — | 预测ID |

### 6.7 数据库服务层设计

#### 6.7.1 模块接口

后端通过 `backend/database/db_service.py` 封装所有数据库操作，上层路由不直接写 SQL。

| 函数 | 参数 | 返回 | 对应用例 |
|------|------|------|----------|
| `get_db_connection()` | — | `pymysql.Connection` | 底层连接 |
| `get_user_by_username(username)` | str | `User \| None` | 登录认证 |
| `check_user_exists(username)` | str | `bool` | 注册检查 |
| `insert_user(user)` | User | `int` (user_id) | 用户注册 |
| `query_sales(...)` | 多维筛选参数 | `dict` (summary + series + by_category + by_region) | UC-01 |
| `export_report(...)` | 报表类型 + 参数 | `str` (文件路径) | UC-09 |

#### 6.7.2 连接管理

- 使用 PyMySQL + DictCursor（返回字典，方便 JSON 序列化）
- `autocommit=False`，由调用方显式 commit/rollback
- 每次查询创建新连接，使用后 `finally` 块关闭，避免连接泄漏
